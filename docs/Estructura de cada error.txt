
Estructura de cada error:

1. line_number:
   Qué representa:
	Representa el número de línea real del archivo CSV donde ocurrió el error.
   Ejemplo:
	Si el error está en esta línea de archivo:
		Línea 8: 
			Y1-013,Masxara silencio,Artesanía,,4,2026-07-11
	Entonces:
		line_number = 8
	Importatne:
		El encabezado cuenta como línea 1. Por eso la promera fila de datos normalmente será la línea 2.

2. column:
  	Qué representa:
		Representa la columna donde ocurrió el error.
	Ejemplos:
		- producto_id
		- producto
		- categoría
		- precio
		- cantidad
		- fecha
	Si el problema afecta toda la fila, se puede usar:
		column = fila_completa
	Ejemplo:
	Si una fila tiene menos columnas de las esperadas, el error no pertenece solo a precio o cantidad, sino a toda la fila.

3. error_type:
	Qué representa:
		Representa el tipo de error detectado.
		Sirve para clasificar el problema de forma ordenada.
	Ejemplos:
		- empty_value
		- invalid_number
		- invalid_integer
		- invalid_date_format
		- missing_column
		- invalid_product_id
		- invalid_text
	Esto ayuda a que el programa sepa qué clase de problema ocurrió.
	

4. message:
	Qué representa:
		Representa el valor original que venía en el CSV antes de validar.
		Sirve para mostrarle al usuario qué dato causó el problema.

	Ejemplos:
		- producto vacío.
		- precio vacío.
		- cantidad inválida. Se esperaba un número entero mayor que 0.
		- formato de fecha inválido. se esperaba YYYY-MM-DD
		- producto_id vacío

5. original_value:
	Qué representa:
		Representa el valor original que venía en el CSV antes de validar.
		Sirve para mostrarle al usuario qué dato causó el problema.
	
	Ejemplos:
		Si el precio venía vacío:
			original_value = ""
		Si la fecha venía así:
			original_value = "07-12-2026"
		si la cantidad venía así:
			original_value = "cinco"

	Esto ayuda mucho para corregir el archivo original.


Estructura de cada error:

1. line_number:
   Qué representa:
   El número de línea del archivo CSV donde se encontró el error, contando el encabezado como línea 1.

2. column:
   Qué representa:
   La columna específica donde ocurrió el error. Si el problema afecta toda la fila, se usará fila_completa.

3. error_type:
   Qué representa:
   La categoría técnica del error, por ejemplo empty_value, invalid_number, invalid_integer, invalid_date_format o invalid_row_structure.

4. message:
   Qué representa:
   El mensaje claro para el usuario final, explicando qué salió mal y qué se esperaba.

5. original_value:
   Qué representa:
   El valor original encontrado en el CSV antes de validar, para que el usuario pueda identificar y corregir el dato incorrecto.
